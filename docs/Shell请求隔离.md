# Shell 请求隔离

0.2.0-beta.4 将快捷目标、Shell 文件图标、媒体缩略图及系统入口图标读取移至独立 STA 进程。工作进程复用 `Lume.exe --shell-worker`，进入专用入口后不读取状态、运行启动项迁移、创建管理窗口或接管桌面。第三方图标/缩略图提供程序阻塞或崩溃时，主界面仍可响应。

## 生命周期与容量

| 边界 | 行为 |
| --- | --- |
| 并发 | 日常运行至多两个工作进程：快捷目标/AI 核对共享一个，文件/媒体/系统图标共享一个；每个进程串行处理 |
| 请求期限 | 默认 3 秒，包含排队、启动、连接和读写；确认进程退出最多另等 1 秒。排队超时不终止他人的执行请求 |
| 卡死/崩溃 | 关闭连接并结束本客户端创建的确切进程；确认未退出时保留所有权，不继续创建进程；失败冷却 5 秒，后续请求可以重启 |
| 容量 | 每客户端至多 256 个待完成请求；管道单帧最多 256 KiB，传回图像为最多 128×128 的原始像素，分配前验证消息长度 |
| 空闲 | 最后一次成功请求 10 秒后退出；采用一次性定时检查，没有无工作进程时的周期轮询 |
| 所属进程退出 | 客户端取消并结束工作进程；独立父进程观察线程也会在父进程退出后结束子进程，即使读取线程卡住 |
| 通信 | 当前用户专用随机命名管道，连接 PID 和握手 PID 必须是创建的子进程；父进程 PID、启动时间、程序路径在子进程校验 |

图标仍复用原有有限缓存、关联变化通知及异步加载；失败使用冻结备用图案，失败缓存保留 5 秒，后续加载重试。进程空闲退出后首次新请求需要重新启动，因此隔离以故障恢复为优先，会有短时额外 CPU 和内存开销，不代表全程序总内存下降。

工作进程避开主界面启动方法的 JIT 初始化，128 像素图像用软件绘制。Windows 11 本机完整验收包的单次对照，读取同样的 URL、文件和回收站图标后，工作进程私有内存约 98.20 → 80.63 MiB；仅握手时约 39.99 MiB。挂起测试约 317.66 ms 返回并确认进程已退出，400 个排队请求约 102.02 ms 收敛。数值属于指定隔离样例，版本/运行时及 Shell 提供程序会影响结果，不能替代实际桌面总内存测试。

## 扫描和操作

每轮快捷目标读取有 8 秒总预算，剩余预算传到单次请求。超时仍保留文件，并仅复用元数据未变化的旧目标；失败请求不作为成功结果缓存。提示按目录合并，完整扫描重试。已知归类暂时保持，保护不写入 `Overrides`；手动固定优先，撤销和释放固定也可恢复前一有效归类。信息恢复后继续正常自动归类。

手动拖入只保存文件引用，目标在后续后台扫描补齐。应用 AI 建议先后台核对所选文件和快捷目标，再检查期间是否有状态变化；取消、读取失败或过期结果均不提交，仍支持整批撤销。

目录枚举和基础文件元数据仍在现有后台扫描中；用户主动预览正文与原生右键菜单也不属于本隔离通道。这不是文件系统沙箱，不保证第三方 Shell 提供程序没有自身副作用。

## 验证

`scripts/verify.ps1 -SkipInteractive` 先构建专用验收包，运行 `--shell-worker-self-test` 并将结果复制到 `artifacts/verification-0.2.0-beta.4/shell-worker-result.json`。28 项检查覆盖真实图标/网页快捷方式、不改写原文件、并发复用、无限挂起、Dispatcher 响应、确认进程消失、冷却重启、排队风暴、取消、异常退出、空闲回收、所属进程强制退出和损坏 IPC 消息。

正式包不包含 `hang`、`crash`、`echo` 或测试父进程入口；正式包拒绝验收命令。测试只使用自身进程、隔离文件和未显示的管理窗口，不移动鼠标，不重启 Explorer，不调用桌面接管。

实际毫秒与临时进程内存以验收结果为准。该检查不能证明真实 Explorer 重启、休眠、多屏或完整 8 小时桌面运行通过。
