# 过期引用清理

从 0.2.0-beta.5 起，“设置 → AI 与数据 → 过期引用 → 检测并清理…”提供记录清理。它只移除已删除文件留下的自动归类记录和学习样本，不删除、打开或移动原文件。

## 使用

1. 点击“检测并预览”。首次确认文件缺失时开始计时，检测时间随数据保存。首次检测通常没有候选。
2. 默认等待 30 天后再次检测；也可选择 7 / 90 天。等待期依据两次检测之间的时间，并不表示程序已连续监测每天的文件状态。
3. 检查候选列表及完整路径，勾选确认，再点击“备份并清理”。更改等待期会使原预览失效。
4. 程序先保存并校验完整备份，再重新检测候选；文件已返回、目录身份变化或配置/文件快照变化时，整批清理不提交。
5. 成功后可在窗口“撤销本次清理”，或通过整理历史按顺序撤销。重启后、历史移入较早分段后仍可恢复失踪文件的原归属与学习样本。

备份位于数据目录旁的 `Lume-backups/before-reference-cleanup-*.lume-backup.zip`；通常是 `%LOCALAPPDATA%\Lume-backups`。它包含真实路径及账户加密的 AI 设置，请私下保管。

## 保留条件

手动固定、外部文件引用、手动排序中列出的路径、当前文件视图中的项目，以及不属于当前关注目录第一层的路径全部保留。清理不会移除 Overrides、LinkedFiles、手动顺序或历史分段。

缺失检测只接受本地固定磁盘上的关注目录。隐藏/系统文件仍按存在处理；网络目录、可移动盘、路径中的目录联接/符号链接/离线标记、无法读取的目录或文件，都不作为缺失证据。部分 OneDrive 路径会因此显示“无法确认”。

目录身份包含卷序列号、文件编号与创建时间。相同路径重新建立目录、失联、文件返回或检测时间倒退时，等待期重新开始。单次请求最长 3 秒，整次检测预算 15 秒，每批最多 32 个名称；超时或未返回的路径保留。检测在临时独立工作进程进行，关闭窗口可取消，不在界面线程等待磁盘。

## 数据格式与占用

检测记录作为主状态的一部分备份；仅执行清理后，状态升级为格式 3，以保留移除归属的撤销数据。beta.1–beta.4 无法直接读取格式 3，回退须使用清理前完整备份。执行撤销仍保留格式 3，不自动降级。

清理减少当前状态中的路径记录以及后续读取、复制与保存的工作量。完整备份和撤销历史仍保存原数据，因此磁盘总占用不一定下降。历史、备份和 AI 设置有各自用途，不应为追求体积直接删除其依赖。

## 验证范围

核心回归覆盖等待期、身份变化、失联、手动保护、备份失败、并发过期、取消、写入回滚、重启/归档撤销及旧格式备份恢复。独立 WPF 验收使用虚构本地文件，实际点击控件事件，验证隐藏文件保护、IPC、预览、清理和撤销；窗口位于屏幕外，不模拟键鼠，不接管 Explorer。它不代表所有真实云目录或移动盘环境均已验收。
