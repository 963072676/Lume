# 图标状态与后续缺口（2026-09-23）

本页记录当前源码的修复与下一轮验收；已发布的 `0.2.0-beta.1` 不包含本页修复。完成代码检查不等于用户桌面和发布包已经验收。

## 覆盖范围与本轮修复

Windows“桌面图标设置”常见的五项已覆盖：此电脑、回收站、网络、用户文件、控制面板。入口遵循系统显示设置；其他文件、快捷方式与应用图标由普通桌面分区显示。暂不增加固定的第六项，以免把用户文件夹、应用或云盘入口误当作所有机器都有的系统图标。

| 场景 | 发现的问题 | 当前源码处理 | 验收证据 |
| --- | --- | --- | --- |
| 回收站空、满 | 系统入口创建时只读取一次图标 | 常驻消息窗口接收 Shell 通知；后台查询全盘回收站项目数，选择空/满图标；350 毫秒合并事件，30 秒低频兜底 | 空/满图标像素不同；系统通知配合注入的项目数驱动屏幕外分区从空→满→空，计数提示同步更新 |
| 管理窗口隐藏 | 监听若依附管理窗口，常驻期无法保证注册 | 独立消息窗口在主窗口构造时注册，关闭时注销；无文件路径的系统入口通知刷新五项入口，其他入口每五分钟低频校验 | 验收检查隐藏管理窗口仍注册并收到 Shell 通知，且非回收站入口也刷新 |
| 快捷方式图标资源 | `.ico` 等资源变化不会按快捷方式目标路径失效 | 读取快捷方式的 `IconLocation`；资源文件及其父目录变化时清除相关缓存并刷新已加载卡片 | 两种路径的缓存失效测试；原有不同图标、更新快捷方式、失效路径回归 |
| 文件、目标和关联 | 缓存可能保留旧图标 | 对文件自身、快捷方式目标、资源目录与关联/系统图像变更分别失效；过期异步结果不覆盖新图 | 图标定向验收 29 项；最终源码的核心 111/111、菜单/图标/功能/界面/性能/保护自动检查通过；真实桌面交互按脚本参数跳过 |

通知不携带可靠文件路径时，回收站直接重查状态。`SHCNE_UPDATEIMAGE` 携带的是图像索引而非文件 PIDL，因此接收器不会把它当路径解引用。[Shell 通知事件定义](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shchangenotify)、[通知注册说明](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shchangenotifyregister)、[回收站查询接口](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shqueryrecyclebinw)。

## 下一轮按优先级验收与开发

| 优先级 | 工作 | 完成标准 |
| --- | --- | --- |
| P0 | 用新构建在真实 Explorer 桌面验证回收站生命周期 | 仅用可识别的测试文件执行移入、恢复及清空，核对 Lume 和系统图标、提示文字、延迟；保护原有回收站内容，记录前后状态；退出后原桌面恢复。隔离 Shell 通知测试不能代替这一项 |
| P0 | 发布前构建与说明收敛 | 完整自动验收、版本与变更记录、全新发布包校验、升级/回退路径；发布说明写明真实桌面未验收场景 |
| P1 | 长时间与环境验收 | 8 小时有效常驻记录、Explorer 重启、休眠唤醒、显示器插拔和混合缩放；保留失败诊断和恢复证据 |
| P1 | Shell 扩展慢/阻塞及图标队列拥塞 | 用可控的慢处理器复现，确保图标请求不无限排队、可见卡片能重试且界面不阻塞；同时测量 CPU、内存、句柄 |
| P2 | 额外系统入口和图标外观 | 先收集真实用户场景；仅将 Windows 可识别且可配置的入口加入默认列表，图标资源遵循系统个性化设置 |
| P2 | 服务器 CI 预览退出异常 | 定位 Windows Server 上 `ntdll.dll / 0xc000000d`；在定位前继续将该阶段标为跳过，不把 CI 成功当成 Windows 客户端实机预览验收 |

这份顺序以“图标状态真实可见”和“异常退出后桌面可恢复”为发布门槛。新的系统入口与视觉素材排在后面，避免增加默认噪声或引入来源不明的图标。
