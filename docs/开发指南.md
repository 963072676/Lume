# 开发指南

## 目录

| 路径 | 用途 |
| --- | --- |
| `src/Lume.Core` | 扫描、规则、状态、布局、AI 请求与归档 |
| `src/Lume.Desktop` | WPF 界面、桌面分区、托盘与 Windows 集成 |
| `src/Lume.Shell` | C++ 原生桌面右键菜单 |
| `tests/Lume.Core.Tests` | 无外部测试框架的核心回归程序 |
| `tests/Lume.Desktop.Verification` | 仅验收包编译的界面与桌面检查 |
| `scripts` | 构建、验收、打包与菜单诊断 |

产品直接使用 .NET / Windows API，没有第三方 UI 框架。桌面菜单命令从 C# 清单生成到 C++，避免两端漂移。
原生编译通过 `invoke-native-build.ps1` 在指定工作目录运行，恢复调用目录后输出日志，支持外接 `Tee-Object` 的相对路径。失败保留两个输出流并报错；7 项虚构管道检查随自动验收执行，不操作桌面或真实配置。
主窗口按文件、规则与历史、设置分开维护；共享控件样式位于 `Styles.xaml`。

## 构建与检查

环境要求见 [README](../README.md)。所有命令在仓库根目录的 PowerShell 7 中执行。

```powershell
dotnet run --project tests/Lume.Core.Tests -c Release
./scripts/build.ps1
./scripts/build.ps1 -FrameworkDependent
./scripts/verify.ps1 -SkipInteractive
./scripts/verify.ps1
./scripts/package.ps1
./scripts/package.ps1 -FrameworkDependent
./scripts/test-release-packages.ps1
./scripts/check-release-packages.ps1
```

`verify.ps1` 构建独立验收包，执行核心、菜单、图标、功能、界面和桌面交互检查。
每个阶段同时检查进程退出、结果文件时间和明确的成功标志；报告必须是含布尔值 `passed=true` 的 JSON 对象。`test-verification-result.ps1` 的 13 项虚构 JSON 检查覆盖字段缺失、错误类型、数组和截断内容，拒绝将这些报告当作成功。
`-SkipInteractive` 跳过真实鼠标悬停与桌面交互，适用于自动构建环境，不能替代完整桌面验收。
结果保存在 `artifacts/verification-<版本>/`；截图与独立运行数据位于 `artifacts/verification-app/`。
正式构建不包含 `EnableVerification=true` 的测试入口。
`--palette-self-test` 仅在验收包中验证查询合并、取消、过期结果、重复执行及辅助名称；屏幕外窗口禁用激活和焦点请求，不操作系统键鼠。它不替代真实键盘、输入法或读屏验收。
`--accessibility-self-test` 读取实际 WPF 自动化属性，验证归档、规则、AI 和搜索字段的名称、帮助、密码控件语义与文件选中状态，并核对辅助执行回调和键盘菜单的屏幕定位。`FileTileButton` 提供异步辅助执行，普通按钮单击不打开文件；禁用、隐藏或排队后失效的图块拒绝执行。检查窗口不激活、不出现在任务栏，用计数回调代替打开文件，不发送键鼠输入或打开原生菜单；它不等于读屏软件或真实键盘实机验收。
GitHub 构建机以 `LUME_VERIFY_SOFTWARE_RENDERING=1` 对验收包启用软件渲染，避免依赖虚拟显卡；正式包忽略此开关。本地默认仍验证正常渲染路径，软件渲染通过不代表 GPU 兼容性通过。
CI 使用 `windows-2025` 镜像，显式传入 `-SkipFeaturePreview`，`coverage-result.json` 记录跳过范围。Server 2022/2025 在功能预览验收完成后的退出阶段触发 `ntdll.dll / 0xc000000d`，排除媒体控件后仍可复现，根因待定位。本地 Windows 11 完整功能预览验收通过，发布前必须运行不带 `-SkipFeaturePreview` 的检查。CI 仍执行核心、原生恢复、菜单、图标、主界面、目录恢复与性能；不将服务器上被跳过的预览项计作通过。

`--demo --action settings` 可查看演示管理界面，数据位于程序旁 `demo-data`。演示仍会临时挂载真实桌面；退出恢复桌面。
同一时间只运行一个管理桌面的实例。请勿在重要桌面操作期间执行交互验收。

`--card-query-self-test` 使用 26,001 项虚构文件和实际卡片控件验证首次共享结果、独立搜索/排序、分页、折叠、元数据与选择。调用与桌面刷新相同的批次函数，卡片不显示、不创建窗口句柄、不附着 Explorer，加载事件只在控件内触发；它不证明真实桌面渲染、拖放或焦点行为。
`Organizer.QueryCollectionViews` 在单批内共用目录分组与排序，并按每个分区的搜索文本分别筛选。同一视图和文本的结果在本批复用，之后不保留筛选结果；超大分组和排序继续临时处理，索引及排序各自保持 25,000 项引用上限。`DesktopSurface` 在创建和刷新卡片时提供该批结果，卡片自身搜索与分页仍可单独更新。

## 版本与发布

`Directory.Build.props` 是程序版本和构建脚本的共同来源。调整版本时同步说明文档与 `app.manifest` 中四段式程序集版本。
GitHub Actions 在推送和 Pull Request 时运行核心回归、非交互 WPF 主界面、原生恢复、性能检查及两种正式包构建；功能预览和真实桌面验收在本地执行。
提交前验证 `git diff --check`。更新 `docs/releases/<版本>.md` 后，为已验证提交创建 `v<版本>` 标签；流水线成功后自动发布两个 ZIP 与各自 `.sha256` 文件。标签必须匹配源码版本，带连字符的版本标记为预览且不替换稳定版。
构建 SDK 固定在 `global.json`；升级 SDK 时重新验证。包内 `build-info.json` 记录提交、是否存在未提交改动、SDK 和包类型，不记录构建机路径。完整包从本次还原的运行时包复制许可证及第三方声明。CI 产物应满足 `dirty=false`，下载内容以 SHA-256 核对。
打包只读取 `release-files.txt` 中的分发文件，不带演示数据、测试输出或调试符号。
`test-release-packages.ps1` 用 36 个合成 ZIP 检查包身份、字段类型、清单、文件和哈希；合成可执行文件仅为文本，不执行。`check-release-packages.ps1` 要求两个正式包属于当前提交，并核对 `dirty=false`、`verification=false`、运行环境和许可证；逐文件比对本地目录与 ZIP 后，确认 7 个非交互验收入口均以退出码 2 拒绝。CI 在上传附件前执行这两项，报告为 `artifacts/release-package-validation-result.json` 和 `artifacts/release-packages-result.json`。核对当前程序版本的另一已提交构建时可显式传入 `-Source <完整提交>`；新发布仍须提交源码后构建。

CI 中的 Action 固定到从官方仓库核对的完整提交 SHA，并保留版本注释；`checkout` 不在后续步骤保留 Git 凭据。`.github/dependabot.yml` 每周一北京时间 09:00 检查 Action 更新，通过 Pull Request 运行现有检查后再审阅，不自动合并。更新时核对官方标签对应的提交以及所需运行环境，不能只改版本注释。参见 [GitHub 的固定提交建议](https://docs.github.com/en/actions/reference/security/secure-use#using-third-party-actions)与 [Dependabot 配置](https://docs.github.com/en/code-security/reference/supply-chain-security/dependabot-options-reference)。
Windows 构建使用 `windows-2025`；来源证明与发布使用 `ubuntu-24.04`，与 beta.8 成功发布的系统系列一致。固定系列仍会收到镜像更新；切换系统系列前应验证下载、来源证明和发布流程。[GitHub 已宣布](https://github.com/actions/runner-images/issues/14748) `ubuntu-latest` 于 2026-10-19 开始向 Ubuntu 26.04 迁移，本项目不随该别名自动切换。

## 数据兼容与本地文件

程序版本与状态格式版本独立；可读取格式 1 / 2 / 3。旧格式首次保存迁移为 2，只有执行过期引用清理才升级为 3；回到 beta.1–beta.4 前须恢复清理前完整备份。
真实运行数据位于 `%LOCALAPPDATA%\Lume`，不属于源码仓库。

性能优化版首次保存迁移为状态格式 2：设置独立保存，历史使用内容校验的分段文件，活动历史最多 200 条；格式 1 仍可加载，迁移原件保存在 `.legacy.bak`。备份/搬迁时必须包含 `state.json*` 文件和 `state.json.history` 目录。格式 2 应使用当前程序读取，不可直接交给旧二进制。

原生构建同时生成 `Lume.Guard.exe`。`tests/Lume.Recovery.Tests` 在屏幕外临时窗口上验证正常退出、强制终止、身份不符和损坏租约，不操作 Explorer。`--performance-self-test` 验证真实目录事件风暴、失联恢复和无变化同步；追加 `--soak-minutes 480` 执行 8 小时隔离 WPF 常驻测试，结果写入验收包旁 `performance-verification/<id>`。这些不等于真实休眠/多屏/Explorer 接管验收。
`.gitignore` 保留本地 SDK、构建产物、工具状态与诊断文件在本机使用，同时排除它们进入 Git。
排除规则无法取代提交审查，公开前仍应检查凭据、个人路径与截图内容。
