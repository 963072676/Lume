# 升级与回退

0.2.0-beta.4 是预览版。读取旧状态格式 1，首次启动先完整备份再迁移为格式 2；0.1.0 不能直接读取迁移后的状态。从 beta.1 / beta.2 / beta.3 升级不再次迁移格式。

## 升级

1. 从托盘退出 Lume，确认桌面恢复；保留旧程序目录。
2. 在资源管理器地址栏打开 `%LOCALAPPDATA%`，复制整个 `Lume` 文件夹到独立备份位置。这里包含配置、历史、AI 设置和归档记录；只复制 `state.json` 不够。
3. 将新 ZIP 解压到新目录，保留全部随包文件，运行 `Lume.exe`。
4. 在“设置 → 关于”核对版本和程序目录，检查分区、规则、历史与主题。首次迁移的完整备份保存在 `%LOCALAPPDATA%\Lume-backups\before-upgrade-*.lume-backup.zip`，并保留 `state.json.legacy.bak`。后者只代表旧配置，不含后续操作。
5. 如果原先启用了 Lume 开机启动，程序先备份旧命令再迁移到当前路径；备份为同目录 `startup-before-*.json`。原先关闭的启动项不会自动开启，未知命令不会被覆盖。升级后请保留当前程序目录。

启动新版本却仍运行另一目录的旧程序时，会显示旧版本和路径；先退出原版本再重试。beta.4 的“AI 与数据”页可导出 `.lume-backup.zip`，包含配置、分段历史、布局、AI 设置和归档日志。它不包含真实桌面文件、诊断日志或恢复租约。

格式 2 的状态依赖 `state.json*` 文件及 `state.json.history` 目录，不要单独清理这些文件。Windows 当前用户加密的 AI 密钥不保证跨电脑、跨账户可用，迁移后可重新填写。

## 回退

退出新程序，先额外备份当前整个数据目录，保留升级后产生的记录。将升级前的整个数据备份恢复到 `%LOCALAPPDATA%\Lume`，再启动旧程序。

使用完整 ZIP 时，可在 beta.4 的“AI 与数据”页选择“恢复完整数据备份”。程序校验清单、文件哈希和历史依赖，确认后退出重启；替换前将当前整个目录保留为 `%LOCALAPPDATA%\Lume-before-restore-*`。校验失败不替换当前数据。恢复旧格式备份后，beta.4 会再次按升级流程迁移；如要退回 0.1.0，应退出所有实例后将 ZIP 中的数据文件手动还原到 `Lume`，不要复制 `lume-backup.json` 清单，再启动旧程序。

回退旧程序还需在旧版重新设置开机启动和桌面菜单，防止入口继续指向新版。

回退会回到备份时的配置和历史；升级后新增的记录留在新格式备份中，不能由旧程序读取。物理归档涉及真实文件移动：回退配置不会逆转磁盘操作。若升级后执行过物理归档，请先在新程序中核查归档与恢复记录，避免旧记录和实际文件位置不一致。

## 配置损坏

启动提示恢复时，程序会先校验备份并保留损坏原件；也可在设置页使用恢复功能。没有有效备份时，保留整个目录并提交脱敏诊断，不要反复删除状态文件。历史导出含真实路径，不应上传公开 Issue。
