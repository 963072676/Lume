# 2026 年 10 月复盘与优化

本次复盘更新至 0.2.0-beta.10 源码。已补齐升级恢复、计算响应、慢 Shell 请求隔离、过期引用清理、大目录查询及输入的辅助名称；发布情况以发布页面实际附件为准。保持预览版，尚不足以声明所有 Windows 桌面场景已稳定。

## 已完成

| 原问题 | 当前行为与验证 |
| --- | --- |
| 解压新版本后可能仍唤起旧目录程序，启动项也保留旧路径 | “关于”显示实际运行信息；发现另一目录的实例时显示旧版本与路径；已有启动项先备份再迁移，未知或关闭的启动项保持原状。隔离注册表验证 |
| 仅备份主配置不能覆盖分段历史和 AI 设置 | 完整 ZIP 包含配置、设置、历史及归档日志；恢复前验证清单、哈希和依赖，保留当前整份目录后替换。跨分段历史、篡改、缺失依赖和路径越界回归 |

折叠卡片在 beta.2 已不会创建文件图块；本次只进一步提前跳过分页和签名计算，不能把此前误判当作新增大幅性能提升。

## 性能证据

Windows 11、.NET 10.0.11、Release、同机合成数据的单次前后诊断：

| 场景 | beta.2 | 本次实现 |
| --- | ---: | ---: |
| 5,000 文件 / 30 条未匹配扩展名规则，预热后逐项匹配 | 182.18 ms / 112.31 MiB 临时分配 | 22.50 ms / 88 B 临时分配 |
| 100 个 121 字符名称，`^(a+)+$` 压力正则 | 6,241.10 ms | 32.03 ms，含首次准备 |

这些是受控计算样例，不能推出真实进程总内存、所有正则或所有机器的提升幅度。新的 7 次采样基准还测量批量匹配，使用源码中的宽松退化门槛；运行方法见[性能复测](性能复测.md)。后向引用和环视等不支持线性引擎的正则仍沿用带超时的兼容引擎。

beta.5 的同机查询基准：1 万文件 / 60 分区重复搜索，41.17 ms / 14.75 MiB 临时托管分配降到 1.13 ms / 0.094 MiB；首次查询 7.29 ms / 2.18 MiB。缓存不保留历次搜索结果，超出引用上限时临时处理。减少当前状态中的路径记录不等于删除备份和撤销数据，不能声称磁盘总占用同步下降。

beta.6 的十万文件无匹配查询从 19.21 ms / 10.68 MiB 临时托管分配降至 1.37 ms / 584 B（7 次采样中位数），未包含调度、输入合并或 UI 渲染。快速操作上限为 20 个分区和 40 个文件，超出时提示缩小范围；它与文件视图的 80 项分页不同。

beta.7 补充了同根映射的共享桶与只读排序/筛选视图，分别保持 25,000 项引用上限。极端的 1 万文件 / 60 同根映射重复查询从 254.21 ms / 41.94 MiB 临时分配降到 0.26 ms / 0.090 MiB；首轮 7.46 ms / 2.37 MiB。普通十万文件超出缓存范围仍需要临时分组与排序；不要将共享目录压力测试推导为所有目录的同等提升。
