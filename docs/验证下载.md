# 验证下载

从本项目的 GitHub Releases 获取完整包或精简包及同名 `.sha256`。beta.5 起，标签发布工作流在 Windows 验收和打包通过后，为下载的两个 ZIP 生成 GitHub/Sigstore 构建来源证明，再发布。

## SHA-256

在下载目录用 PowerShell 检查：

```powershell
Get-FileHash -LiteralPath .\Lume-0.2.0-beta.5-win-x64.zip -Algorithm SHA256
Get-Content -LiteralPath .\Lume-0.2.0-beta.5-win-x64.zip.sha256
```

哈希应完全相同。精简包使用其同名校验文件。

## 发布来源

已安装 GitHub CLI 时，检查发布包是否由本项目的指定标签工作流产生：

```powershell
gh attestation verify .\Lume-0.2.0-beta.5-win-x64.zip --repo 963072676/Lume --signer-workflow 963072676/Lume/.github/workflows/ci.yml --source-ref refs/tags/v0.2.0-beta.5 --deny-self-hosted-runners
```

来源证明绑定 ZIP 的哈希、仓库、源码引用和工作流。请检查验证结果中的源码提交、标签和工作流是否对应目标版本。若缺失证明或验证失败，不应宣称验证通过。更详细的机制与命令见 [GitHub 官方说明](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations)和 [CLI 文档](https://cli.github.com/manual/gh_attestation_verify)。

本地自建便携包有自己的哈希和 `build-info.json`，不会拥有 GitHub 工作流对另一份 ZIP 生成的证明。即使源码提交相同，打包时间和构建环境也可能使 ZIP 哈希不同。

来源证明用于检查下载包和构建来源，不替代 Windows Authenticode 代码签名，不消除 SmartScreen 提示，也不代表所有运行场景已通过验收。当前程序尚未代码签名；支持范围见随包《支持与已知问题.md》。
